- Consequence: Any future divergence from the SDKs' rules — a rule the vendor adds in an SDK release, or a Java rule that drifts — is invisible until a live 422. ## validation-3. [medium, behaviour-gap] CONFIRMED: A 422 request-validation body is quoted verbatim; both SDKs extract the field path and message

- Reference does: The JS SDK flattens FastAPI's `detail` array into a dotted path and message, pinned by test: `{detail: [{loc: ["body","questions","q","score","criteria"], msg: "Input should be a valid list"}, {loc: ["body","questions"], msg: "Dictionary should have at least 1 item"}]}` becomes `"questions.q.score.criteria: Input should be a valid list; questions: Dictionary should have at least 1 item"` (test/errors.test.ts:69-82), and `{detail: {error_type: "api_usage_error", message: "Unknown model: x"}}` becomes `"Unknown model: x"` (test/errors.test.ts:63-66). - Refuter's evidence: Java: /Users/jim/src/typesafe-client/typesafe-client/src/main/java/software/sava/typesafe/exceptions/TypeSafeRequestException.java:36-40 builds the message from `quoted`, the raw body truncated at `MESSAGE_BODY_LIMIT = 512` (:13), and the class comment at :8-9 states the deliberate choice. Mirror `extract_message` at /Users/jim/docs/ai/typesafe/typesafe-sdk-python/src/typesafe_sdk/_core/errors.py:39-65 (not schemas/base.py:24, which is response-validation path formatting) and pin it with the JS fixtures at /Users/jim/docs/ai/typesafe/typesafe-sdk-js/test/errors.test.ts:59-94, including the no-message fallback case.
